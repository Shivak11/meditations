# Concise meditation format

The approved revision replaces the reader-facing long reflection format in both editions. Retain the five-R reasoning privately. Begin with a direct summary of the work or session, with a short additional-topic sentence and compact topic links only when useful. Each actual topic has, in order, a plain topic heading, an immediately emphasised one-sentence principle, a brief factual account of how it emerged, and one concrete application. Provisional ideas stay provisional. Do not invent a unifying theme, discovery story, topic, outcome or universal rule.

Each concept occupies at most one readable A4 page. Put the opening with the first topic. Edit the content rather than shrinking type or hiding essential explanations. Preserve natural phone scrolling. No fixed topic count, palette, font or industry example. Keep explanations literal and connected, with no decorative metaphors, stacked labels or italics. Review all visible, accessible, interactive and printed prose independently of design.

Counterexamples and next experiments remain reasoning tools; show them only when they materially explain a principle, without compulsory extra panels or topics. Deliver a brief link and any actual recording decision in ordinary language. No mandatory closing checklist or internal record-state labels in study/chat. Retain recording states and evidence privately. Current explicit preferences are sufficient direction; clarify only material uncertainty.

Preserve each edition's authorised context and lasting-record approval boundaries. Public instructions and examples are neutral and self-contained. Do not copy private client material, identity details, transcripts, configuration, or local paths into the public repository. Public offline random fallback designs and root ZIP remain supported. SHVA retains private context access. No personal duplicate skill installation.

## Ownership and execution

Use isolated worktrees. The SHVA worker owns only shva/skills/meditate/**, using the canonical local skill as the input because its visual/language updates are not on origin/main. The orchestrator owns public skill/docs/package/evaluations, SHVA help/metadata/release records and installation. Evaluation agents own separate output directories outside either repository. Preserve other edits; on unexpected mtime changes copy the foreign file and git diff immediately before stopping to resolve the collision.
